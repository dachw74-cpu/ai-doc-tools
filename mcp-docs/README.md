# agentdocs — MCP-сервер инструментов рабочей папки «Агент»

Слой доступа к документам и данным проекта для агентов VS Code (и любых других MCP-клиентов).
Только чтение: сервер не меняет документы и не пишет файлы на диск.

```
tools\mcp-docs\
├── server.mjs      — MCP over stdio (JSON-RPC 2.0), чистый Node.js, без зависимостей
├── py\docs.py      — разбор docx / xlsx / HTML-MHTML (Python 3.13 + lxml + openpyxl)
├── py\rag_search.py — поиск по локальному RAG-индексу боевых документов (fastembed/ONNX, без GPU)
├── check.ps1       — вызов инструментов из командной строки (обход проблем с кириллицей в argv)
├── selftest.py     — быстрый прогон Python-части на реальных файлах
├── smoke.mjs       — самотест всего MCP-протокола как настоящий клиент
└── smoke-report.json — отчёт последнего самотеста
```

## Инструменты

| Инструмент | Что делает |
|---|---|
| `read_docx` | текст, заголовки (`mode: outline`), таблицы документа Word |
| `read_xlsx` | листы, размеры, предпросмотр строк книги Excel |
| `read_html_export` | HTML/MHTML-выгрузки (Confluence и т. п.) в markdown, включая зачёркнутые варианты |
| `docx_revisions` | отслеженные правки и комментарии: автор, дата, текст |
| `docx_check` | целостность, обязательные части, XML, макросы, внешние ссылки, сравнение с оригиналом |
| `search_text` | поиск по текстовым файлам рабочей папки с контекстом |
| `find_files` | инвентаризация файлов: имя, расширение, свежесть |
| `bpmsoft_lookup` | банк вопросов сертификации BPMSoft по номеру, теме или словам |
| `meeting_transcript` | живая расшифровка встречи: идёт ли запись, роли, последние реплики |
| `finals_audit` | инвентарь «Финальных документов» с SHA-256 и сверка с манифестом |
| `search_docs` | **смысловой (RAG) поиск по боевым документам**: топ-k фрагментов с точной ссылкой (файл, лист/абзацы), косинусом и лексическим покрытием; `answer_found=false` + `warning` — в документах прямого ответа нет |
| `rag_info` | состояние RAG-индекса: модель, размерность, число чанков, актуальные файлы, дубли |

### RAG-поиск (`search_docs`)

Индекс строится отдельно и лежит в `рабочие\rag_эп\index` (читает его MCP, пишет — `рабочие\rag_эп\rag_build.py`):

```
py -3 -X utf8 рабочие\rag_эп\rag_build.py --dir "<папка с docx/xlsx>" --out "<...>\index"
```

**Модель эмбеддингов.** По умолчанию — локальный fastembed (`MiniLM-L12-v2`, 384 измерения).
Его окно — 128 токенов, а медиана наших чанков — ~390, поэтому 99.6% фрагментов он видит
только началом. Для полноценного индекса собираем через API:

```
py -3 -X utf8 рабочие\rag_эп\rag_build.py --dir "<папка с docx/xlsx>" --out "<...>\index" \
    --provider api --api-model text-embedding-3-large --api-batch 64
```

Ключ (`tools\mcp-docs\py\embed_api.py`) берётся из переменной `AIAI_API_KEY` либо из конфига
Chatbox — провайдер с тем же хостом; в файлы и логи не пишется. В `manifest.json` пишутся
`provider`, `model`, `dim`, `usage` (токены). Поиск сам выбирает способ эмбеддинга запроса
по `provider` в манифесте — трогать `rag_search.py` при смене модели не нужно.
⚠️ **Косинус у API-моделей живёт в другом диапазоне** (лучший 0.35–0.65 против 0.55–0.73 у MiniLM),
поэтому пороги калибруются под конкретную модель и под IDF-веса лексики, а не берутся из головы.

Эталон для проверки качества: `рабочие\rag_эп\bench.py` (12 контрольных вопросов с опорными
строками + 6 негативных), сравнивает два индекса по hit@1/hit@3 и ложным «ответ найден».
Калибровка порогов — `рабочие\rag_эп\calib.py` (снимает сигналы с живого `rag_search` и
перебирает сетку порогов, считая FN/FP), ранги верных чанков при разных k слияния —
`рабочие\rag_эп\rank_check.py`. Отчёт 26.10.2026 (пороги пересчитаны + гибрид с BM25):
hit@1 7/11 → 8/11, hit@3 9/11 → **11/11** (нашлись «МЧД» и «MongoDB»: косинус ставил их на 113-е
и 9-е место, BM25 вернул в топ-3), ложные ответы на негативах 1/4 → **0/4**.

Поиск гибридный: косинус сливается с BM25 по тем же 5-символьным стемам (Reciprocal Rank Fusion,
`RRF_K=7`) — BM25 вытаскивает фрагменты с редкими терминами, которые косинус пропускает.

Две ступени доверия к ответу, потому что одного косинуса мало:

- **косинус** — смысловая близость (порог `min_score` 0.30 — только отсечка шума);
- **лексическое покрытие `lex`** — доля *веса IDF* содержательных терминов запроса (без стоп-слов и
вопросительных слов, с учётом русских окончаний по 5-символьному стему), реально найденных во
фрагменте. Служебные термины («доработку» → стем «работ») весят почти ничего, редкие («MongoDB») — много.

Правило: warning «ответа нет» даётся, когда `lex < lex_min` (0.40) **и** либо косинус `< cos_sure` (0.44),
либо лексика `< lex_floor` (0.30). Третий порог — плата за тематически близкие, но неотвеченные вопросы:
«какая стоимость лицензий BPMSoft по прайс-листу» даёт косинус 0.51 (выше честного позитива с SSL 0.46),
и отличает его только отсутствие лексической опоры (lex 0.17). Пороги выбраны серединами плато из
`calib.py` (`cos_sure` 0.30–0.80, `lex_min` 0.25–0.65, `lex_floor` 0.05–0.55).
Параметры `lex_min` / `cos_sure` / `lex_floor` можно передавать в вызове.

Текст фрагмента обрезается до `max_chars` (медианный чанк длиннее окна — 61% чанков > 1200 знаков),
поэтому при необходимости окно сдвигается к первому совпадению с термином запроса и помечается «…»:
иначе найденный фрагмент не показывает ответа (так терялись «МЧД» и «MongoDB»).

По умолчанию ищет только по актуальным документам (`primary`); `history: true` добавляет черновики и бэкапы.

## Подключение в VS Code

Файл `.vscode\mcp.json` в корне рабочей папки уже настроен (`kind: workspace`):

```json
{ "servers": { "agentdocs": { "type": "stdio", "command": "<node.exe>", "args": ["<путь>\\server.mjs"] } } }
```

- Подключить в **другой рабочей папке** — скопируйте `.vscode\mcp.json` туда: пути абсолютные, работает где угодно.
- Подключить **для всех папок сразу** — перенесите блок `servers` в `%APPDATA%\Code\User\mcp.json`.
- Для глобального конфига Copilot — `~\.copilot\mcp-config.json` (там ключ `mcpServers`).

Важно: `command` должен указывать на настоящий Node.js (`C:\Program Files\nodejs\node.exe`).
`node` из PATH — это Electron, он работает иначе и обрезает вывод при `process.exit()`.

## Проверка

```
node tools\mcp-docs\smoke.mjs                # весь протокол + все инструменты на реальных файлах
py -3 -X utf8 tools\mcp-docs\selftest.py     # только Python-часть (docx/xlsx/MHTML)
```

Ожидаемый итог: все вызовы `OK`, кроме намеренно ошибочного (несуществующий инструмент).
Полный прогон включает `search_docs` (холодный вызов ~3.5 с) и `rag_info`. Если индекс ещё не собран — эти два
вернут `ok: false` с подсказкой, остальные инструменты продолжат работать.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `AGENT_ROOT` | корень рабочей папки «Агент» | два уровня выше `server.mjs` |
| `AGENT_PYTHON` | путь к python.exe с lxml/openpyxl | `…\Python313\python.exe` |
| `AGENTDOCS_DEBUG` | `1` — отладка в stderr | выключено |

## Как добавить инструмент

1. Функция-обработчик в `server.mjs` (возвращает `ok(obj)` или `fail('текст')`).
2. Запись в массиве `TOOLS`: `name`, `title`, `description`, `inputSchema`, `handler`.
3. Сложный разбор документа — команда в `py\docs.py` + запись в `COMMANDS` + вызов через `runPy()`.
4. Прогон `node tools\mcp-docs\smoke.mjs` и добавить кейс в `smoke.mjs`.

## Грабли, уже пройденные

- **PowerShell 5.1 и JSON в аргументах** — строка с пробелами оборачивается в кавычки и ломает JSON.
  Поэтому аргументы передаются файлом: `docs.py <команда> @args.json` (см. `check.ps1`).
- **BOM** — PowerShell пишет UTF-8 с BOM; `.live_session.json` и манифесты читаются через `readJsonSafe()`.
- **`.ps1` из этой папки — только UTF-8 с BOM** (PS 5.1 иначе читает файл как ANSI и портит кириллицу).
- **Расширение врёт** — тип файла определяется по содержимому (`sniff()`): `.doc`, внутри которого MHTML,
  и `.docx`, внутри которого обычный docx, разбираются правильно, с честной подсказкой при несовпадении.
- **`numbering`, сноски, колонтитулы** — текст берётся из `word/document.xml` (плюс контейнеры `sdt`,
  текстовые поля); нумерация списков не восстанавливается.
